- Training 표본도 같은 7종, 비율도 거의 같다(CV 45.6 / OG 38.1 / TM 7.5 / AF 6.2 / FD 1.5 / TR 1.0 / NW 0.1).
- **PS(인물)·LC(장소)·DT(날짜)·QT(수량)가 없다.** 일반적인 한국어 NER(KLUE 등)과 다른 체계이므로 공개 모델을 그대로 쓸 수 없고, 라벨 매핑도 불가. 공식 태그 정의는 AI Hub 데이터 설명서에서 확인 필요(다운로드 폴더에 설명서 없음).
- **극심한 불균형**: CV+OG가 82%, NW는 0.1%(Val 12,074개). 태그별 F1을 따로 봐야 하고, 소수 태그는 표본에서 비율을 올리거나(over-sampling) 최소 수량을 보장해야 한다.

## 4. 데이터 품질 문제 (설계에 직결)

### 4-1. 기사 꼬리말·상용구가 개체로 대량 라벨링됨
- CV 상위 2위 `저작권자` 287,496개, OG 상위 1~3위 `뉴스1코리아`·`공감언론 뉴시스통신사`·`공감언론 뉴시스` 합계 약 44만 개, TM에 `yns4656@` 같은 **이메일 아이디** 수만 개.
- 가장 많이 반복된 문장(400파일 표본): `무단전재-재배포 금지.>` 6,756회, `<저작권자 © 뉴스1코리아, 무단전재 및 재배포 금지>` 1,048회, `xxx@(이메일)<저작권자ⓒ 공감언론 뉴시스통신사.` 류 다수, `= .` 218회.
- 동일 문자열 문장 중복: Validation 7.4%, Training 표본 3.4%.
- **영향**: 이런 문장을 그대로 학습하면 모델이 "저작권자=CV, @=TM"을 외워 점수는 오르지만 의미 없는 성능. 평가에서도 부풀려진다. → **상용구 문장 제거·중복 제거 후 평가**가 필수.

### 4-2. 라벨 위치가 없고, 같은 텍스트가 문장에 여러 번 나오는 경우 라벨은 1개
- 개체 텍스트가 문장에 없는 경우 0% (좋음).
- 문장 내 2회 이상 등장하는 개체 12.2%(Val), 11.3%(Train 표본). 이때 같은 (text, tag) 라벨이 두 번 들어간 경우 0% → **"한 번 라벨 = 모든 출현"으로 해석하는 것이 자연스럽다**(사전 매칭 방식으로 라벨링된 흔적).
- 설계 결정: 모든 출현에 태깅(all-occurrence)을 기본으로 하고, 첫 출현만(first-occurrence)과 비교 실험.

### 4-3. 개체 경계의 74%가 어절 경계가 아니다
- 개체 양쪽이 공백인 경우 25.6%뿐. 개체 바로 뒤에 **한글(조사 등) 44.2%**(은·는·에·의·이·가·들·을·과·를·와·로…), 괄호·따옴표·쉼표 등 22.3%.
- 예: `광주교대와`, `임차인이`, `항공기를`, `포스트 코로나를`.
- **영향**: 어절 단위 BIO 태깅은 불가능. **문자 오프셋 기반**으로 span을 만들고, 토크나이저의 offset mapping으로 서브워드에 라벨을 입혀야 한다(한국어 NER의 표준 처리). 또한 모델이 "조사 앞에서 끊기"를 배워야 하므로 경계 오류가 주요 오류 유형이 될 것.

### 4-4. 중첩·겹침과 태그 모호
- 겹치는 개체 쌍 8,770(표본 47.7만 개체 중 약 1.8%). CV–CV, OG–OG, OG–CV 조합이 많음(예: 긴 기관명 안의 짧은 기관명).
- 같은 텍스트가 다른 태그로 쓰인 종류 3,696/89,887(4.1%): `새누리당` AF/OG, `롯데백화점` AF/OG, `검찰` CV/OG, `영어` CV/FD, `학` AF/CV/TM.
- 명백한 오라벨: `자유한국당`→AF, `lg화학`→FD(‘화학’ 부분 매칭), `sk건설`→TR, `한화`→FD. 한 글자 개체 124,566개(`시`가 FD로 50,960개 — 詩/市 구분 없음).
- **영향**: 평면(flat) NER로 가려면 겹침 해소 규칙(긴 span 우선)이 필요. 태그 모호·오라벨은 **라벨 노이즈율**로 추정해 보고서에 적어야 하며, 사람이 100~200개를 직접 검수한 수치가 설득력을 만든다.

### 4-5. 카테고리 편차
- 개체 밀도(개체/기사): 정치 23.2, 산업 16.2, 경제 15.2 … 연예 6.4, 문화 7.1. 경제·산업·정치 기사에 OG가 집중.
- Validation과 Training의 카테고리 구성이 다름(Val은 연예 1위, Train 표본은 경제 1위). 출처 사이트 구성도 다름(Val 뉴시스·뉴스1·스타뉴스, Train 뉴스1·머니투데이·뉴시스·머니S). → 평가 세트를 Validation에서 뽑으면 **자연스러운 도메인 이동(domain shift)** 평가가 된다.

## 5. 설계로 이어지는 결론

| 발견 | 설계 결정 |
|---|---|
| 규모 과다 | 카테고리 층화 표본: 학습 6만 · 개발 1만(Training) / 평가 1만(Validation) 문장 수준에서 시작. 소수 태그(NW·TR·FD) 포함 문장 최소 수량 보장 |
| 상용구·중복 | 정규식 필터(저작권자·무단전재·(이메일)·©/ⓒ·`= .`) + 문장 중복 제거. 필터 전/후 두 조건으로 학습·평가해 효과를 수치로 |
| 위치 없음·복수 출현 | 모든 출현 태깅 기본. 첫 출현만과 비교(H2) |
| 어절 경계 아님 | 문자 오프셋 span → 토크나이저 offset mapping → 서브워드 BIO. 평가는 문자 span 단위 정확 일치 |
| 겹침·모호·오라벨 | 겹침은 긴 span 우선. 태그 모호 텍스트는 다수결로 정제(선택). 라벨 노이즈율은 수동 검수 100~200건으로 추정 |
| 불균형·카테고리 편차 | 태그별·카테고리별 F1 보고. 경제·산업·정치 카테고리를 별도 평가(팀 관심: 금융·경제 도메인) |
