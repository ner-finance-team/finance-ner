## 1. Problem Definition

### 1.1 문제점 : 니즈

금융 기사와 리포트에는 "어느 회사가 · 언제 · 얼마를 · 몇 %로" 같은 핵심 정보가 문장 속에 흩어져 있다.

> 미래에셋증권은 3분기 영업이익이 2,450억원으로 전년 대비 12.5% 증가했다고 밝혔다.

이 문장에서 투자 분석, 공시 모니터링, 금융 검색·RAG 시스템이 필요로 하는 정보는 **기관(미래에셋증권), 기간(3분기), 지표(영업이익), 금액(2,450억원), 비율(12.5%)**이다. 사람이 기사를 하나씩 읽으며 정리하기에는 양이 너무 많고, 숫자는 한 글자만 틀려도 정보의 의미가 바뀐다.

LLM으로도 정보를 뽑을 수 있지만 출력이 확률적이고 개체의 정확한 시작·끝 위치를 보장하지 않는다. "2,450억원으로"에서 **"2,450억원"까지만 정확히 잘라내는** span 단위 개체 인식이 필요하다.

### 1.2 Task Reformulation

- **초기 접근:** "원본 개체 7종으로 학습한 모델을 그대로 금융 기사에 쓰고, 금융 라벨은 LLM으로 붙인다."
  → 문제점: ① 원본에는 금액·비율·날짜·지표 라벨이 아예 없다. ② 금융기관 이름이 정확히 OG로 라벨된 비율이 54.8%뿐이고, 하나카드·우리카드처럼 TM으로 붙은 경우도 있어 기존 라벨을 금융 정답으로 그대로 쓸 수 없다. ③ 수십만 문장을 LLM으로 라벨링하는 것은 시간·비용상 어렵고, LLM 라벨을 정답으로 쓰면 평가의 근거가 약해진다.
- **현재 접근:** 두 단계로 나눈다.
    1. **1단계: 일반 뉴스 NER 기본 모델.** 원본 7종(CV·OG·TM·AF·FD·TR·NW)을 17개 분야에서 고르게 뽑은 30만 문장으로 학습한다. 팀 공용 데이터와 채점기로 후보 모델을 비교한다. → *Named Entity Recognition / sequence labeling*
    2. **2단계: 금융 특화 NER로 추가 학습.** 말뭉치의 경제 분야 문장(5,398,845개)에 금융 라벨 7종(+선택 1종)을 새로 정의한다. 학습용 라벨은 규칙·사전·1단계 모델로 자동으로 붙인 **선라벨(실버셋)**을 쓴다. 평가는 팀원 5명이 선라벨을 직접 검수해 만든 **골드셋 500문장**으로 한다. → *Domain Adaptation + Weak Supervision*

> **용어** — **선라벨**: 사람이 보기 전에 규칙·사전·1단계 모델로 자동으로 붙인 라벨. **실버셋**: 선라벨만 붙은 학습용 문장(양은 많지만 틀린 라벨이 섞임). **골드셋**: 사람이 한 문장씩 검수한 평가용 문장(양은 적지만 정확함). 이번 프로젝트에서 LLM은 라벨링에 쓰지 않는다.

### 1.3 Task 설계

- **Task:** Named Entity Recognition (문장 단위 span 예측)
- **입력:** 한국어 경제·금융 기사 문장 / **출력:** `[(시작 위치, 끝 위치, 개체 유형), ...]` (원문 글자 위치, 끝은 포함하지 않음)
- **AI 관점에서 어려운 점과 접근**
    1. **정답 부족:** 금융 라벨이 없고 기관명 라벨은 부정확하다. → 규칙·사전으로 선라벨을 붙여 실버셋으로 학습하고, 사람이 검수한 골드셋으로 평가한다(약지도 학습).
    2. **위치 없음:** 원본 라벨에 텍스트만 있다. → 문장에서 위치를 찾아 span 정답으로 바꾼다.
    3. **한국어 경계:** "삼성전자는"처럼 조사가 붙고, 토크나이저가 단어를 쪼갠다. → 글자 위치 기준으로 채점하고, 토크나이저별로 낼 수 있는 최대 점수를 측정한다.
    4. **분야 변화와 망각:** 일반 뉴스로 배운 모델이 금융에서도 통할지, 금융으로 더 배우면 일반 뉴스 성능이 떨어질지 알 수 없다. → 추가 학습 전후를 둘 다 측정한다.
    5. **선라벨 흉내:** 모델이 선라벨로 배우면 규칙·사전을 따라 하기만 할 수 있다. → 선라벨 자체를 골드셋으로 채점해 기준점으로 두고, 모델이 이보다 나은지 확인한다.
- **성공 기준** (개체 단위 엄격 일치 micro F1. 0.7점 미만 차이는 표본 흔들림 범위로 보고 "차이 없음"으로 판단)
    - 골드셋에서 2단계 모델이 **선라벨 자체 점수**보다 높다.
    - 골드셋에서 **1단계 모델 출발(②)**이 **사전학습 모델 출발(①)**보다 높다.
    - 골드셋 검수의 팀원 간 일치율(공통 40문장, span F1)이 0.8 이상이다.

**금융 NER 라벨 정의 (v1)**

| 라벨 | 정의 | 예시 |
| --- | --- | --- |
| **FIN_ORG** | 금융회사와 금융 감독·정책 기관 | 우리은행, 한국투자증권, 금융위원회, 금감원, 한은 |
| **ORG** | 그 밖의 기업·기관·단체 | 삼성전자, 네이버, 국토교통부 |
| **FIN_PRODUCT** | 금융상품의 구체적 유형이나 상품명 | ETF, 회사채, 주택담보대출, 체크카드 |
| **MONEY** | 금액 (숫자+단위+통화) | 5000억원, 1조원, 3만원 |
| **RATE** | 비율·금리 값 (숫자+%·%p·bp) | 3.5%, 0.25%p |
| **DATE** | 날짜·기간 (절대·상대·기간) | 2026년 10월, 지난해, 3분기 |
| **INDICATOR** | 경제·금융 지표와 기업 재무지표 | 코스피, 기준금리, 영업이익, 환율 |
| POLICY *(선택)* | 금융·부동산 정책·규제·세제 | DSR, LTV, 종합부동산세 |

경제 문장 10만 개 표본에서 각 라벨 후보가 한 번이라도 나온 문장 비율: INDICATOR 17.5%, RATE 15.9%, DATE 15.8%, MONEY 15.1%, FIN_PRODUCT 9.5%, 금융기관 이름 6.9%, 금융당국 4.1%, POLICY 2.5%.

**경계 규칙 (팀 공통 기준)** — AI Hub 공식 지침(문맥 우선, 최장 단위, 조사·어미 제외, 괄호 규칙)을 따르고 아래를 더한다.

- 하나의 대상이면 여러 어절도 하나로 묶는다: "KB국민은행 강남지점" → `KB국민은행 강남지점`
- 개체 뒤 조사는 뺀다: "우리은행은" → `우리은행`
- 숫자 라벨은 숫자와 단위까지만 쓰고, 앞뒤 수식어(약·최대·이상·가량)는 뺀다: "약 5,000억원" → `5,000억원`
- 지표와 값은 따로 붙인다: "기준금리 3.5%" → `기준금리`(INDICATOR) + `3.5%`(RATE)
- 시점·지역 수식어는 분리한다: "지난해 영업이익" → `지난해`(DATE) + `영업이익`(INDICATOR)
- 코스피·코스닥은 지수를 뜻하면 INDICATOR로 붙인다(원본에서는 OG).
- 애매한 사례는 라벨링 가이드 예시 목록에 계속 추가하고, 팀원 간 일치율이 낮은 유형부터 정리한다.

**기존 7종과의 관계**

| 기존 | 2단계 처리 |
| --- | --- |
| OG | FIN_ORG / ORG / INDICATOR(코스피·코스닥)로 다시 판정. 선라벨 후보로만 쓰고 정답으로 그대로 쓰지 않는다 |
| TM | 카드사명·서비스명이 섞여 있어 참고만 하고 자동으로 바꾸지 않는다 |
| CV·AF·FD·TR·NW | 2단계 라벨에서는 쓰지 않는다 |
| PERSON | 원본에서 인물명이 `(이름)`으로 가려져 있어 학습할 수 없다 |

**최종 산출물:** 금융 라벨 정의서·라벨링 가이드, 전처리 코드와 데이터 구축 기록, 1단계 모델 비교표, 범용·금융 특화 모델 비교표, 오류 분석 보고서, 문장을 넣으면 개체를 보여 주는 데모

### 1.4 이 문제가 중요한 이유

- **금융 정보 자동화의 첫 단계:** 공시·뉴스 모니터링, 기업별 실적 정리, 금융 지식 그래프, RAG의 메타데이터 생성은 모두 "누가·언제·얼마"를 정확히 뽑는 것에서 시작한다.
- **숫자 정확도가 곧 신뢰도:** 금액·비율의 경계가 틀리면 잘못된 수치가 그대로 분석에 들어간다.
- **도메인 적용의 현실적 문제를 검증:** 공개된 한국어 금융 NER 데이터를 찾지 못했다. 현장에서도 원하는 라벨이 갖춰진 데이터는 드물다. 기존 라벨 재활용, 규칙·사전 선라벨, 소량의 사람 검수로 도메인 모델을 만드는 과정 자체가 다른 분야(의료·법률 등)에도 적용할 수 있는 방법론이다.

## 2. Background & Baseline

### 2.1 Related Works

- **규칙·사전 기반:** 금액·비율·날짜처럼 형식이 정해진 개체는 정규식으로 높은 정밀도를 얻을 수 있다. 하지만 사전에 없는 이름이나 문맥에 따라 달라지는 개체는 처리하지 못한다.
- **통계·신경망 모델 (CRF, BiLSTM-CRF):** 태그 순서를 고려한 시퀀스 라벨링으로 NER의 표준이 되었으나 특징 설계나 대량의 라벨 데이터가 필요하다(Lample et al., 2016).
- **사전학습 언어모델 (BERT 계열):** BERT(Devlin et al., 2019), RoBERTa(Liu et al., 2019), ELECTRA(Clark et al., 2020) 위에 토큰 분류층을 붙여 파인튜닝한다. 한국어는 KLUE(Park et al., 2021)의 KLUE-BERT·KLUE-RoBERTa, KoELECTRA가 공개되어 있다.
- **도메인 적응:** 범용 모델을 특정 분야 데이터로 추가 학습하면 그 분야 성능이 오르는 경우가 많지만(Gururangan et al., 2020), 데이터 품질·양·라벨 일관성에 따라 효과가 달라지고 기존 분야 성능이 떨어지는 망각 현상이 생길 수 있다(Kirkpatrick et al., 2017).
- **약지도 학습(weak supervision):** 사람 라벨이 부족할 때 규칙·사전으로 만든 자동 라벨로 학습하고 소량의 사람 라벨로 평가한다(Ratner et al., 2017; NER 적용은 Liang et al., 2020). 자동 라벨의 누락·오류가 모델에 그대로 학습될 수 있다는 한계가 있다.
- **LLM 기반:** 학습 없이 지시문과 예시로 개체를 추출할 수 있지만, 출력 위치가 부정확하고 비용·속도 면에서 대량 처리에 불리하다.

### 2.2 이번 프로젝트의 Baseline

- **1단계 팀 공통 기준선**
    - 모델: `klue/roberta-base` 인코더 + 토큰 분류 선형층(softmax), 일반 교차 엔트로피 손실
    - 라벨: 글자 span → 토크나이저 offset으로 토큰별 BIO 꼬리표(O + 7종×B/I = 15개) → 예측 후 다시 글자 span으로 복원해 채점
    - 설정: 학습 30만 문장(split_v3), 최대 길이 512, 학습률 5e-5, 배치 16, 3에폭, seed 42
    - 성능: **dev F1 0.7466, test F1 0.7306**
- **2단계 기준선**
    - ① **선라벨 자체:** 규칙·사전·1단계 모델 예측으로 붙인 선라벨을 그대로 골드셋에서 채점한 점수(학습 없음)
    - ② **사전학습 모델 출발:** `klue/roberta-base`를 실버셋으로 바로 학습(1단계를 거치지 않음)
- **1단계 후보 모델** (모든 후보는 같은 데이터·같은 채점기로 비교한다)

| 후보 | 사전학습 방식 | 검토 이유 |
| --- | --- | --- |
| klue/roberta-base (기준선) | RoBERTa (개선된 MLM) | 한국어 NER의 표준 출발점이고 성능과 속도의 균형이 좋음 |
| klue/bert-base | BERT (MLM + 다음 문장 예측) | RoBERTa와 구조·크기가 같아 사전학습 방식의 차이만 비교 |
| klue/roberta-large | RoBERTa (개선된 MLM) | 크기(약 1.1억 → 3.4억 파라미터)를 키웠을 때의 효과와 비용 |
| monologg/koelectra-base-v3 | ELECTRA (대체 토큰 판별) | 사전학습 방식이 다른 공개 한국어 모델 |
| AI Hub ELECTRA 1세부·2세부 | ELECTRA (AI Hub 공개) | 같은 AI Hub 말뭉치 계열에서 사전학습된 모델 |
| klue/roberta-base + CRF 헤드 | RoBERTa + CRF | 꼬리표 순서 규칙을 학습해 경계 오답이 줄어드는지 |
| klue/roberta-base + 가중 손실 | RoBERTa | 드문 태그(NW·TR·FD)에 벌점을 키워 macro F1이 오르는지 |
| klue/roberta-base·AI Hub ELECTRA + 형태소 입력 | (입력 변경) | 형태소 경계에 공백을 넣으면(Kiwi) 경계를 더 잘 맞히는지 |

**예비 실험 결과 (1단계)**

- **학습량 곡선** (klue/roberta-base): 1,500 / 6,000 / 2만 / 6만 / 20만 / 30만 문장. 20만 → 30만에서 dev F1 +1.55점 → 학습량 30만으로 확정(30만: dev 0.7466, test 0.7306).
- **표본 흔들림:** 6만 문장 서로 다른 표본 A·B·C, 같은 표본 시드 42·1·2로 점수 편차를 쟀다. 이 편차를 근거로 "0.7점 미만 차이는 차이 없음"으로 정했다.
- **후보 모델 비교** (학습 6만 문장 split_v1 기준, 그 밖의 설정은 기준선과 같음)

| AI Hub ELECTRA 1세부 | 형태소 입력(Kiwi) | 0.6849 | 0.6690 | 0.4556 |
| **klue/roberta-base** | **CRF 헤드** | **0.7110** | **0.6984** | 0.4828 |
| klue/roberta-base | 가중 손실(weighted CE) | 0.6949 | 0.6780 | **0.5094** |

- CRF 헤드가 dev·test 모두 가장 높아(기준선 대비 dev +0.81점), 30만 문장으로 다시 학습한 **CRF 30만 모델을 2단계 출발점**으로 쓴다.
- roberta-large는 학습률·배치가 다른 모델과 달라 직접 비교에 주의한다.
- test의 NW는 19개, TR은 126개뿐이라 이 두 태그의 F1과 macro F1은 흔들림이 크다.

## 3. Proposed Method

### 3.1 핵심 아이디어

1. **공용 정답·공용 채점:** 모든 팀원이 같은 데이터(split_v3)와 같은 채점기를 써서 모델을 공정하게 비교하고, 점수뿐 아니라 오답까지 비교해 출발 모델을 고른다.
2. **앙상블:** 예측을 글자 위치로 저장하므로 토크나이저가 다른 모델끼리도 합칠 수 있다. 다수결로 단일 모델보다 높은 점수를 노린다. 조합은 dev로 정한다.
3. **2단계 학습:** 1단계 모델(CRF 30만)의 본체를 이어받고, 분류층만 새 라벨 수(2×라벨 수+1)로 새로 만들어 금융 실버셋으로 추가 학습한다.
4. **실버셋·골드셋 분리:** 학습은 규칙·사전 선라벨(실버셋)로만 하고, 평가는 사람이 검수한 골드셋 500문장으로만 한다. LLM은 라벨링에 쓰지 않는다.

### 3.2 Baseline 대비 무엇이 다른가

| 항목 | Baseline | 제안 방법 |
| --- | --- | --- |
| 라벨 체계 | 원본 7종(일반 뉴스) | 금융 7종(+POLICY) |
| 금융 개체 인식 | 규칙·사전 선라벨 그대로 | 선라벨로 학습한 모델(문맥으로 일반화) |
| 기관명 | 원본 OG(금융기관 정확 라벨 54.8%) | FIN_ORG / ORG / INDICATOR로 다시 판정 |
| 학습 출발점 | 사전학습 모델(klue/roberta-base) | 1단계에서 NER을 이미 배운 모델(CRF 30만) |
| 평가 정답 | 원본 라벨(누락 포함) | 사람이 검수한 골드셋 |

**전처리**

| 단계 | 처리 | 결과 |
| --- | --- | --- |
| ① 위치 복원 (라벨 → span) | 라벨 텍스트를 문장에서 찾아 글자 위치 `(시작, 끝, 태그)`로 바꾼다. 끝 위치는 포함하지 않는다(`text[시작:끝]`). | TL1 5,856만 문장 → span 7,838만 개, 못 찾은 라벨 1개 |
| ② 반복 개체 처리 | 같은 텍스트가 한 문장에 여러 번 나오면 모든 위치를 정답으로 표시한다. 겹치면 긴 span을 우선하고, 길이가 같으면 앞에 있는 것을 우선한다. | 원본 라벨 6,943만 개보다 span이 많아짐 |

| ⑦ 선라벨 (2단계) | MONEY·RATE·DATE는 정규식, FIN_ORG는 금융회사·당국 목록 + 1단계 모델의 OG 예측, ORG는 1단계 모델의 OG 예측 중 나머지, INDICATOR·FIN_PRODUCT·POLICY는 사전으로 붙인다. 겹치면 긴 span을 우선한다. | 실버셋, 골드셋 검수용 초안 |
| ⑧ 골드셋 검수 (2단계) | 10문장으로 기준을 맞춘 뒤, 각자 맡은 문장의 선라벨을 고친다(추가·삭제·경계·유형 수정). 공통 40문장으로 일치율을 재고, 갈린 유형은 가이드에 추가한다. | 골드셋 500문장 |

### 3.4 왜 효과가 있을 것으로 예상하는가 (검증 대상 가설)

**1단계: 일반 뉴스 NER**

- **H1. 데이터 양:** 학습 문장이 많을수록 F1이 오를 것이다. (결과: 20만 → 30만, dev +1.55점)
- **H2. 학습 횟수:** 3에폭 이후에는 더 학습해도 크게 오르지 않을 것이다. (결과: 5에폭, 차이 0.5점 이내)
- **H3. 가중 손실:** 드문 태그에 벌점을 키우면 macro F1이 오를 것이다. (결과: macro F1 +4.1점, 대신 흔한 태그를 더 놓쳐 micro F1 -0.7~1.2점)
- **H4. CRF 헤드:** 꼬리표 순서를 학습하면 경계 오답이 줄어 F1이 오를 것이다. (결과: 6만 기준 dev +0.81점, test +1.18점)
- **H5. 앙상블:** 여러 모델을 다수결로 합치면 단일 모델보다 F1이 높을 것이다. (test 참고값 +1.8점. 조합은 dev로 다시 정하고 test는 마지막에 한 번만 채점한다)

**2단계: 금융 특화**

- **H6. 학습 효과:** 선라벨로 학습한 모델은 문맥까지 배우므로 사전·규칙에 없는 표현도 잡아, 골드셋에서 선라벨 자체보다 F1이 높을 것이다. 반대로 선라벨의 오류도 함께 배워 정밀도는 선라벨보다 낮을 수 있다.
- **H7. 출발점 효과:** 1단계 모델은 기관명(OG)을 이미 배웠으므로, 사전학습 모델에서 바로 학습한 것보다 FIN_ORG·ORG F1이 높을 것이다.
- **H8. 망각:** 금융 데이터만 학습하면 일반 뉴스의 기관명 인식이 떨어지고, 일반 뉴스 문장을 섞어 학습하면 덜 떨어질 것이다.
- **H9. 라벨 기준의 명확성:** 같은 라벨링 가이드로 검수하면 팀원 간 일치율이 0.8 이상일 것이다. 낮은 라벨은 기준 자체가 애매하다는 뜻이므로 정의를 고친다.

| 번호 | 실험 | 목적 | 상태 |

| 실험 2 | 학습량(1,500~30만)·에폭·표본 흔들림 | 학습량·에폭 결정, 차이 판단 기준 | 완료 |
| 실험 3 | 30만 문장으로 상위 모델 재학습 + 앙상블(dev로 조합 선택) | 1단계 최종 모델 | 진행 |
| 실험 4 | 2단계 기준선: 선라벨 자체를 골드셋으로 채점 | H6 | 예정 |

| 실험 7 | ③ 경제 문장으로 사전학습을 더 한 본체에서 출발 | 도메인 적응 사전학습 | 시간 되면 |

설정(학습률·에폭)은 1단계 기준선(5e-5, 3에폭, 배치 16, 최대 길이 512)에서 시작하고 dev로만 조정한다. 모든 후보에 같은 횟수의 조정 기회를 준다.

### 4.2 비교 축

- **모델:** 사전학습 방식(BERT·RoBERTa·ELECTRA), 크기(base·large), 헤드(softmax·CRF), 손실(CE·가중), 입력(원문·형태소)
- **데이터량:** 1,500 ~ 30만 문장
- **학습 출발점:** 사전학습 모델 vs 1단계 NER 모델 vs 도메인 적응 사전학습 모델
- **학습 데이터 구성:** 금융 실버셋만 vs 일반 뉴스 혼합
- **평가 분포:** 일반 뉴스 test / 금융 골드셋
- **비용:** 학습 시간, 추론 속도, 파라미터 수
- 비교할 축 외의 조건은 고정한다. 결과는 공용 채점기 형식으로 저장하고, 결정과 근거를 함께 기록한다.

### 4.3 Evaluation Metrics 및 검증

**지표 설계**

- **주 지표:** 개체 단위 micro F1(엄격 일치). 시작 위치, 끝 위치, 태그가 모두 맞아야 정답이다. 금액·날짜는 경계가 한 글자만 틀려도 정보가 틀리기 때문이다.
- **보조 지표:** 정밀도, 재현율, macro F1, 라벨별 F1, 분야별 F1, 오답 유형 5가지(경계 / 유형 / 경계+유형 / 오탐 / 미탐), 학습·검증 loss 곡선
- **참고 지표:** 토큰·글자 정확도. 대부분이 '개체 아님'이라 늘 높게 나오므로 비교에는 쓰지 않는다.
- **데이터 사용 규칙:** dev는 설정 선택에만 쓰고, test와 골드셋은 최종 모델 평가에 한 번만 쓴다.
- **최종 보고:** 1단계 test 리포트, 2단계 골드셋 리포트, 문장 입력 데모

**지표 검증 방법**

- 정답 파일을 예측으로 넣으면 F1 = 1.0이 나오는지, 경계를 한 글자 바꾼 예측이 '경계' 오답으로 분류되는지 확인하고, seqeval 결과와 대조한다.
- 토크나이저 상한 F1을 모델별로 기록해 점수 차이가 토크나이저 때문인지 구분한다.
- 시드를 바꿔 2~3회 반복해 점수 편차를 확인한다(0.7점 기준).
- **골드셋 신뢰도:** 공통 40문장에서 팀원끼리 span F1(일치율)을 잰다. 라벨별 일치율도 함께 보고한다.
- **선라벨 품질:** 선라벨을 골드셋으로 채점해 라벨별 정밀도·재현율을 보고한다(= 실버셋에 섞인 오류의 크기).
- **한계 명시:** 골드셋은 선라벨을 보고 고친 것이라 선라벨 쪽으로 기울 수 있다. 이 경우 선라벨로 학습한 모델의 점수가 실제보다 높게 나올 수 있어 보고서에 함께 적는다.
