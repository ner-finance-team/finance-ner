# 2026-10-21 회의록 — NER 팀 1차 회의

- 참석: 전원 (김병석, 김현호, 박규태, 진태현, 최세진)

## 논의 사항

### 1. 진행 순서 (2단계)
- **1단계 순수 NER:** 과제 요구대로 데이터의 개체 7종(CV·OG·TM·AF·FD·TR·NW)을 인식하는 모델을 먼저 만든다.
- **2단계 도메인 특화:** 1단계 모델을 특정 도메인(카테고리)으로 파인튜닝해 성능이 달라지는지 검증한다. 도메인에 맞는 세부 라벨링도 진행한다.

### 2. 문제 정의
- 원칙: "라벨을 정한다"가 아니라 "어떤 문제를 풀기 위해 어떤 정보를 추출할 것인가"를 먼저 정하고, 그 목적에 맞는 라벨을 정한다.
- 데이터셋 라벨은 만든 사람의 목적에 맞춰 붙은 것이다. 우리 목적과 같으면 그대로 쓰고, 다르면 빼거나 더하거나 수정한다.
- 활용 시나리오 후보: IT/클라우드 뉴스의 기업·기술 정보 추출, 금융 문서의 주요 개체 식별, 상품 리뷰의 브랜드·제품명 추출, 문서 검색·RAG용 메타데이터 생성.

### 3. 엔티티·입출력 정의
- 1단계는 데이터가 정한 7종을 그대로 쓴다. 인물·장소·날짜 태그는 데이터에 없다(인물명은 `(이름)`으로 비식별). 정의된 태그 밖의 개체는 버린다.
- 입력: 문장 1개 / 출력: 개체 span 목록 `(시작 글자 위치, 끝 글자 위치, 태그)`. 모델 내부에서는 토큰별 BIO 꼬리표(B/I × 7 + O = 15개).

### 4. 데이터·전처리
- 라벨에 시작·끝 위치가 없으므로 문장에서 개체 텍스트를 찾아 위치를 구한다. 한 문장에 라벨이 여러 개일 수 있다.
- 먼저 EDA를 하고 데이터 분석 보고서를 작성한다(모델 후보 선정 근거이자 발표 자료).

### 5. 2단계 도메인 라벨 재정의 방안
- 기본 모델은 기존 7종 그대로 학습하고, 금융 파인튜닝 단계에서는 필요한 라벨을 직접 붙인다.
- 검토한 방안: LLM 라벨러(라벨 정의서를 프롬프트에 포함, 위치는 코드로 검증, 일부 사람 검수), 골드셋(사람·평가용)/실버셋(자동·학습용) 분리, 1단계 모델로 선라벨 후 교정, 금융기관명·상품명 사전 매칭, 공개 금융 NER 데이터 재사용.

### 6. 아키텍처
- 기본: 한국어 사전학습 언어모델(예: klue/roberta-base) + 토큰 분류 헤드. offset mapping으로 글자 위치 ↔ 토큰 매핑.
- 여러 토큰을 하나의 개체로 묶어야 한다("한국원자력협회"). 학습은 BIO로 나누고 출력에서 합친다.
- 개체의 74%가 조사·괄호 앞에서 끝나므로 공백이 아니라 글자 위치 기준으로 라벨링한다.

### 7. 산출물
- 모델과 함께, 새 문장을 넣으면 개체를 뽑아 보여 주는 데모를 만든다.
- 평가는 개체 단위로 정답과 비교한다.

## 결정 사항
- 진행 순서: 문제 정의(목적·활용 시나리오) → 라벨 정의서 → 각자 모델 학습·비교 → 도메인 특화 파인튜닝
- 활용 시나리오: **금융 문서의 주요 개체 식별** (세부 시나리오는 오후에 각자 고민 후 공유)
- 1단계는 원본 7종 라벨 그대로 사용
- 기존 라벨 체계(7종) 분석 담당: 김현호
- 모델은 각자 분리 학습 후 공유하고, 평가 기준은 공통으로 한다
- 오늘 산출물: 문제 정의 + 라벨 정의서 + 연구 계획서 초안
- 퇴근 전 5분 미팅으로 진행 상황 공유
