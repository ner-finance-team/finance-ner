## 논의 사항

### 1. 데이터 준비
- 원본 전체는 시간·리소스가 부족해 약 30만 건을 샘플링했다. 전원 같은 데이터를 쓴다.
- 파일 구성: 학습 3개 · 검증 · 테스트. 학습·검증·테스트는 반드시 서로 다른 데이터여야 한다.
- 데이터량 확대는 추후 다시 검토한다.

### 2. 공통 평가 노트북
- 최세진이 공통 노트북을 만들어 공유했다. 채점을 동일하게 하고 학습 중 F1 등 지표를 자동 저장한다.
- 노트북은 채점 기준과 결과 수집만 정해 둔 것이다. 모델 설계는 각자 하고, 자기 코드에 평가 부분을 붙인다.

### 3. 모델 설계·하이퍼파라미터
- 설계 변수: 모델 선택, 하이퍼파라미터(학습률·배치·에폭·최대 길이), 데이터량, 라벨 구성.
- 파라미터(가중치·편향)는 학습으로 고쳐지고, 하이퍼파라미터는 설계자가 정한다. 레퍼런스 값으로 시작해 학습하며 조율한다.
- 초기 설정 예시: BERT-base, 학습률 2e-5, 에폭 3, 배치 16~32, 최대 길이 256토큰.

### 4. 모델 분담
- 후보 5개(BERT·RoBERTa 계열, base·large 등)를 선정했다. 클수록 성능은 좋을 수 있지만 느리다.
- 각자 하나씩 골라 학습한다(겹쳐도 됨). 1회 학습에 1~2시간이 걸리고 GPU 크레딧도 소모되므로 모든 조합을 돌릴 수는 없다.

### 5. 중간 결과
- 6만 건으로 BERT-base, RoBERTa-base(가중 손실 포함)를 돌렸고 F1은 약 0.7 수준이다.
- 에폭 3~4 이후 검증 점수가 떨어졌다(과적합) → 검증 점수가 떨어지기 전에 멈춘다.
- 태그별 데이터 불균형으로 드문 태그 성능이 낮고 macro F1이 떨어진다. 데이터 개선 실험을 따로 진행 중이다.

### 6. 평가 지표
- 정밀도 = TP/(TP+FP), 재현율 = TP/(TP+FN), F1은 조화평균. macro는 클래스별 평균, micro는 전체 합산.
- 검증 데이터는 설정 선택, 테스트 데이터는 최종 성능 보고에 쓴다.
- 최종 산출물: 테스트셋 F1 리포트 + 임의 문장 입력 데모.

### 7. 라벨링 툴 시연 (2단계 금융)
- 서버에 라벨링 툴을 올려 사용한다. 문장을 드래그해 태그를 입히고, 태그는 요청하면 추가할 수 있다. 개체가 없는 문장도 '없음'으로 확인해야 완료된다.
- 금융 문서를 받아 인원별로 나눠 라벨링한다.
- 자동 선라벨 후 사람 검수도 검토했으나, 자동화하려면 처음에 사람이 어느 정도 라벨을 붙여야 한다.
- 팀원이 금융 전문가가 아니어서 라벨이 흔들리면 노이즈가 된다. 샘플로 기준을 맞춘 뒤 진행하고, 양보다 품질을 우선한다.

### 8. 강사 질의응답
- **선택 기준:** 한 모델의 하이퍼파라미터는 검증 로스로 고르고, 모델 간 비교는 F1로 한다. 로스 값은 모델끼리 직접 비교할 수 없다.
- **F1 수준:** 절대 기준은 없지만 일반적인 분류 문제라면 0.9 이상은 나와야 한다는 의견. 0.7은 낮다.
- **LLM 비교:** GPT에 태스크·엔티티 정의와 문장을 주고 점수를 내 기준선으로 비교할 수 있다.
- **NER의 의미:** NER은 모델이 아니라 태스크다. 정보 추출·RAG 검색·팩트 검증 같은 큰 시스템의 일부로 쓰인다.
- **가장 중요한 것:** 모델을 돌리는 것보다 문제 정의, 어떤 데이터를 넣고 결과를 어떻게 해석할지가 더 중요하다.

## 결정 사항
- 데이터: 샘플링한 30만 건을 전원 동일하게 사용
- 평가: 최세진 노트북의 채점 방식을 공통으로 사용, 모델 간 비교는 F1
- 모델: 추천 후보 중 각자 하나씩 선택(겹쳐도 됨), 하이퍼파라미터는 추천값에서 시작해 자율 수정
- 기록: 이름 · 모델 · 초기 하이퍼파라미터 · 결과를 표로 기록
- 최종 선택: 결과가 가장 좋은 모델·하이퍼파라미터를 골라 추가 학습(오늘 목표)
- 최종 보고: 테스트셋 F1 리포트 + 문장 입력 데모
- 라벨링: 금융 원문 샘플로 기준을 먼저 맞춘 뒤 인원별로 나눠 진행, 점심 후 함께 검토
